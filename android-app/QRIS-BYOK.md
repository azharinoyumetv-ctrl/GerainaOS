# QRIS and merchant-owned Xendit accounts

DagangOS's subscription-payment account is separate from each Geraina merchant's customer payments. The POS reads only `integrations.xendit` for the authenticated store. There is no fallback to a platform environment key, shared account, platform settlement, application fee or fee subsidy in this path. The merchant supplies their own approved Xendit account, API key and webhook verification token. Xendit processes their customer transactions under that account; provider fees are the merchant's responsibility under their Xendit agreement.

The Android/web integration menu now has a functional QRIS setup page, which points to the existing Xendit credentials. The previous payment-settings QRIS page used an unused merchant-ID field and a fabricated active callback status; it now redirects to the same setup. Merely saving configuration is labelled unverified. Stripe, Telegram and Email SMTP configuration tabs/fields/navigation are removed at the owner's request, and old links redirect to QRIS. Existing stored legacy values are not deleted. Saving a provider sends only that provider, and failures to load settings block saving and offer Retry. The previous blanket "connected" label is removed. Secrets can be managed only by the authenticated store's Owner/admin on the backend.

The payment flow creates an amount-specific dynamic QR using Xendit's v3 Payment Request API. The backend must return a real payment-request ID and QR action before an order can proceed. The POS displays a pending receipt, polls the store-scoped order, and shows paid after the backend receives a valid payment confirmation. Webhooks resolve the store by its own callback token, match the provider request ID where supplied, and verify IDR request/capture amounts. Missing/malformed/wrong amounts do not settle a sale. Duplicate or late pending/failure notifications cannot undo a paid sale. QRIS requests are limited to positive whole-Rupiah amounts up to Rp10 million.

The callback URL for this Geraina deployment is **https://geraina-os.vercel.app/api/webhooks/xendit**. A live routing check found that the old `api.dagangos.com` address returned 404 for this webhook. Version 1.2.4 corrects both setup instructions. The working endpoint rejects invalid tokens with 401. It uses the merchant's saved callback token, without consulting DagangOS subscription credentials.

## Verification and activation

- `backend/tests/test_qris_contract.py` uses an intercepted HTTP transport and isolated in-memory stores. It checks the merchant key (while a different platform key is present), no-key failure, response validation, limits, callback authentication, amount/currency/identity checks, tenant isolation, duplicate/late notifications, secret-free setup status and owner-only secret access. It makes no live payment and changes no merchant data.
- `verify-release-quality.cjs` checks retired routes, partial configurations, failure/retry, one-provider saving, BYOK wording, both QRIS settings entry points and the cashier's pending-to-paid UI using explicit fixtures.
- A read-only inspection of the supplied Geraina account found Xendit inactive with neither API key nor callback token present. No sandbox or live provider payment has been attempted. Provider acceptance, customer payment, callback delivery and settlement therefore remain unverified until the merchant configures its own approved account and performs a controlled test. Credentials must be entered through the store's integration form, not shared in reports/chat.
- Native/emulator tests do not certify payment-provider settlement or physical printer output.
